# העברת האפליקציה לסביבת DEV הפנימית — `transport.js`

| | |
|---|---|
| **כלי** | `transport.js` (בשורש הפרויקט) |
| **מטרה** | איגוד קבצי המקור של `webapp` לקובץ טקסט יחיד שניתן להעביר לסביבה הפנימית |
| **תלויות** | Node.js בלבד (`fs`, `path`) — ללא חבילות חיצוניות |
| **עודכן** | 06/10/2026 |

---

## 1. למה הכלי קיים

סביבת ה־DEV הפנימית מנותקת, והעברת קבצים אליה נעשית דרך ערוץ שמעביר **טקסט בלבד** ומסנן מילות מפתח של קוד. `transport.js` פותר את שתי הבעיות:

1. **איגוד** — כל קבצי המקור נארזים לקובץ טקסט אחד (`transport-bundle.txt`) במקום להעביר עשרות קבצים בנפרד.
2. **עקיפת הסינון** — מילות מפתח כמו `function` מקבלות סיומת (`functionMoAb`) כך שהטקסט עובר את הסינון. הפריקה בצד השני מחזירה אותן בדיוק למצבן המקורי.

הכלי אינו חלק מהאפליקציה ואינו נטען בזמן ריצה.

---

## 2. פקודות

| פקודה | מה היא עושה |
|---|---|
| `node transport.js pack` | **הפקודה הרגילה.** מרעננת את תיקיית ההעברה מקבצי המקור החיים ואז אורזת אותה ל־`transportFiles .dist/transport-bundle.txt` |
| `node transport.js refresh` | מרעננת בלבד — מעתיקה את קבצי המקור לתיקיית ההעברה, בלי לארוז |
| `node transport.js unpack` | פורקת את החבילה חזרה לקבצים בתוך `transportFiles .dist/restored` |
| `node transport.js pack <srcDir> [bundle]` | אורזת תיקייה מפורשת **כמות שהיא**, ללא רענון |
| `node transport.js unpack <bundle> [outDir]` | פריקה ליעד מפורש |
| `node transport.js refresh <destDir>` | רענון ליעד מפורש |

> **שים לב:** `pack` עם תיקייה מפורשת (`pack <srcDir>`) **אינו** מרענן — הוא אורז את מה שנמצא בתיקייה. רק `pack` ללא ארגומנטים מרענן תחילה.

---

## 3. רשימת הקבצים המועברים — `SOURCE_FILES`

`SOURCE_FILES` שבראש `transport.js` היא **מקור האמת היחיד** לשאלה אילו קבצים עוברים ל־DEV. נכון להיום היא מכילה 19 קבצים:

| תחום | קבצים |
|---|---|
| ליבה | `Component.js` |
| Controllers | `App.controller.js`, `Home.controller.js`, `AllEmployees.controller.js`, `ManagerReports.controller.js` |
| Views | `App.view.xml`, `Home.view.xml`, `AllEmployees.view.xml`, `ManagerReports.view.xml` |
| Fragments | `AppHeader.fragment.xml`, `HomeMonthPicker.fragment.xml`, `AllEmployeesViewSettings.fragment.xml`, **`ManagerReportsReminder.fragment.xml`** |
| מודל | `DataService.js`, `formatter.js`, `mockEmployees.js` |
| משאבים | `i18n.properties`, `style.css`, `tokens.css` |

### 3.1 הוספת קובץ חדש

הוסף שורה אחת ל־`SOURCE_FILES` (נתיב יחסי לשורש הפרויקט) — הרענון, האריזה והפריקה מטפלים בו אוטומטית. אין צורך לגעת בשום מקום אחר.

### 3.2 קבצים שאינם ברשימה — במכוון

`webapp/index.html` ו־`webapp/manifest.json` **אינם** נכללים. הם לא השתנו מאז ההעברה הקודמת ובסביבת DEV קיימת גרסה משלהם. **אם אחד מהם ישתנה — יש להוסיף אותו לרשימה לפני ההעברה הבאה.** גם תיקיית `webapp/test/` אינה נכללת (בדיקות אינן רצות ב־DEV).

---

## 4. איך הרענון מבטיח שהקבצים עדכניים

זהו לב העניין: החבילה חייבת לשקף את הקוד החי, לא שארית מהרצה קודמת. הרענון (`refresh`) אוכף זאת בשלושה שלבים:

1. **בדיקת התנגשות שמות** (`assertUniqueBasenames`) — הקבצים נשטחים לשם הבסיס שלהם בתיקיית ההעברה (`webapp/view/App.view.xml` → `App.view.xml`). אם שני נתיבים ב־`SOURCE_FILES` חולקים שם בסיס, האחד היה דורס את השני ורק האחרון היה מגיע ל־DEV — בלי שום סימן. הכלי נעצר עם שגיאה מפורשת במקום לאפשר זאת.

2. **מחיקת שאריות** — כל קובץ בתיקיית ההעברה שאינו ב־`SOURCE_FILES` נמחק. זה הכרחי משום ש־`pack` אורז **כל** קובץ שנמצא בתיקייה, ולא רק את אלה שרועננו. בלי הניקוי, קובץ שהוסר מהרשימה היה ממשיך לנסוע ל־DEV כאילו היה עדכני. קובץ החבילה עצמו (`transport-bundle.txt`) מוחרג מהמחיקה.

3. **העתקה** — כל קובץ ב־`SOURCE_FILES` מועתק מהמיקום החי שלו. קובץ חסר מפיל את ההרצה (`Source file not found`) במקום לייצר חבילה חלקית בשקט.

הפלט מדווח על שני הצדדים — כמה קבצים רועננו וכמה שאריות נמחקו — כך שניתן לוודא בעין את תוכן ההעברה.

## 5. קידוד מילות המפתח

| | |
|---|---|
| **מילות מפתח** | `function`, `if`, `open`, `replace`, `while`, `Object`, `for` |
| **סיומת** | `MoAb` |
| **התאמה** | מילה שלמה בלבד (`\b…\b`) — כדי ש־`notify` לא יהפוך ל־`notifMoAby` |

האריזה מוסיפה את הסיומת, הפריקה מסירה אותה. התהליך סימטרי לחלוטין. הוספת מילה ל־`KEYWORDS` משפיעה אוטומטית על שני הכיוונים — **אך חבילה שנארזה עם רשימת מילים אחת חייבת להיפרק עם אותה רשימה.** אם משנים את `KEYWORDS`, יש להעביר את `transport.js` המעודכן יחד עם החבילה.

## 6. מבנה החבילה

```
***file App.controller.js
<תוכן הקובץ, מקודד>
***file App.view.xml
<תוכן הקובץ, מקודד>
...
```

כל קובץ נפתח בשורת `***file <שם>`, ותוכנו נמשך עד שורת ה־`***file` הבאה. הפריקה מאתרת תחילה את שורות הסימון ורק אז חותכת את הטקסט שביניהן — כך שסופי שורה (CRLF) וקבצים ללא שורה ריקה בסוף חוזרים **בייט בבייט** זהים למקור.

---

## 7. נוהל ההעברה

1. ודא שכל השינויים המיועדים להעברה שמורים בדיסק.
2. הרץ `node transport.js pack`.
3. בדוק בפלט ששמות הקבצים הצפויים מופיעים, ושלא נמחקו שאריות בלתי צפויות.
4. העבר את `transportFiles .dist/transport-bundle.txt` לסביבה הפנימית.
5. בצד השני: `node transport.js unpack <bundle> <outDir>` והעתק את הקבצים למיקומיהם תחת `webapp/`.

> הקבצים נפרקים **שטוחים** — כולם לאותה תיקייה. בצד ה־DEV יש לפזר אותם לתיקיות הנכונות (`controller/`, `view/`, `model/`, `css/`, `i18n/`) לפי מבנה הפרויקט.

### 7.1 אימות אחרי אריזה

כדי לוודא שהחבילה נאמנה למקור, פרוק אותה לתיקייה זמנית והשווה מול הקבצים החיים:

```bash
node transport.js unpack "transportFiles .dist/transport-bundle.txt" /tmp/verify
# ואז השוואת hash לכל קובץ מול מקורו תחת webapp/
```

אימות כזה בוצע בהעברה האחרונה: **19 מתוך 19 קבצים חזרו זהים בייט בבייט**, וללא שאריות של `MoAb` בפלט.
